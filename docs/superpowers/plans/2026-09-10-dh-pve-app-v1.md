# DH PVE App V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `dh_pve_app`, a long-running Python Proxmox VE monitoring agent with MQTT Discovery, event-driven publishing, safe runtime tuning, disk-health evaluation, and autonomous installation.

**Architecture:** One systemd-managed Python process owns one MQTT connection, a scheduler, isolated collectors, a persistent state store, MQTT Discovery, and publish policy. Collectors poll locally; MQTT state is emitted only for significant changes, discrete events, reconnect restoration, or manual refresh. The legacy Bash agent continues running during validation because the new app uses its own MQTT namespace and entity identity.

**Tech Stack:** Python 3, stdlib plus Paho MQTT, systemd, Proxmox/Linux CLI interfaces, pytest/unittest-compatible tests, Bash installer, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-10-dh-pve-app-design.md`

## Global Constraints

- Application name: `dh_pve_app`.
- Type: `linux_agent`.
- MQTT base: `DigitalHouses/Global/dh_pve_app`.
- Home Assistant device name: `DH PVE`.
- New HA entity IDs use `dh_pve_*` and must not collide with legacy `digitalhouses_proxmox_*` entities.
- MQTT Discovery is enabled from first startup.
- No periodic state heartbeat; liveness uses MQTT LWT/availability.
- Manual refresh: `button.dh_pve_refresh` and `sensor.dh_pve_last_refresh`.
- Runtime tuning may be changed from HA only within hard application-defined bounds.
- SMART/disk-health policy is not editable from HA.
- Disk health states: `HEALTHY`, `WARNING`, `CRITICAL`.
- Home Assistant templates do not perform infrastructure health/daily-stat calculations.
- Recorder-facing entities use compact attributes; rich volatile diagnostics are separated.
- Installer must preserve the legacy Bash cron during Phase 1 validation.
- UPS/NUT is out of scope for V1/Phase 1.
